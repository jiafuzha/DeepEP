Current migration guidance
--------------------------

1. Use iSHMEM public APIs over symmetric iSHMEM allocations:
     - ishmem_align / ishmem_free for symmetric buffers
     - ishmem_putmem or ishmem_putmem_nbi for payload movement
     - ishmem_barrier_all / ishmem_sync only where validated

2. Avoid private IBGDA state and WQE manipulation in SYCL:
     - no direct QP lookup
     - no rkey/lkey lookup
     - no mlx5 WQE construction
     - no doorbell or CQ polling code

3. Treat the following as validation-sensitive on the current iSHMEM/IBGDA stack:
     - ishmem_quiet, especially in combine paths
     - iSHMEM atomics
     - P2P pointer mapping / GPU IPC paths
     - concurrent device work-items issuing many iSHMEM puts

4. The current correctness-first normal-mode XPU path should prefer blocking
   ishmem_putmem and explicit phased queue visibility until iSHMEM/IBGDA
   concurrency and completion behavior is characterized by focused tests.
